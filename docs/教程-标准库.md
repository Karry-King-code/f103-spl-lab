## 01 · 环境搭建与脚手架

### 硬件事实表（先过一遍，全部实测/有据）

| 目标 | 引脚/位置 | 怎么知道的 |
|---|---|---|
| 会闪的绿灯 | **PC13**（低电平亮） | 【实测】灯旁丝印 PC13 + 交替闪实验 |
| 继电器（蓝色 SRD-05VDC-SL-C） | **PC14**（低电平吸合，咔哒） | 【实测】咔哒随 PC14 翻转 |
| PWR 红灯 | 电源轨，**常亮不受控** | 【实测】丝印 PWR，通电就亮 |
| 日志串口 | PA9(TX) / PA10(RX)，经 CH340N 到 TypeC | 【文档】原理图 P2 |
| SWD 烧录座 | **核心板左边缘 4P 座：GND / SWCLK / DIO / 3.3** | 【实测】丝印+烧录成功 |
| 晶振 | 8MHz（TKC8.000）→ 系统跑 72MHz | 【实测】丝印 + 1 秒节奏准 |

> ⚠️ 原理图说 PC13=红灯、PC14=绿灯+继电器。**实物实测：PC13=绿灯、PC14 只有继电器**。图和实物有出入，一律以实物为准——这是本教程第一课。

### 步骤 1 · 装软件（一次性）

**在哪看**：装完的软件都要能敲出版本号。
**装什么**：

| 软件 | 干嘛的 | 验证 |

| Keil MDK5（勾选 **AC5/ARMCC** 编译器） | 写代码+编译 | 打开 UV4.exe |

**DFP 怎么装**：下载 `.pack` 双击，或直接解压到下面**两个目录都放一份**（见翻车 #1）：

```
C:\Keil_v5\ARM\PACK\Keil\STM32F1xx_DFP\2.3.0\
C:\Users\<你的用户名>\AppData\Local\Arm\Packs\Keil\STM32F1xx_DFP\2.3.0\
```

### 步骤 2 · 打开工程

**在哪看**：双击 `MDK-ARM\f103-spl-lab.uvprojx`。
**我看到的（实测）**：若弹 Pack Installer 的 `Cannot move file index.pidx` → **点取消**，那是包管理器联网刷新失败，跟编译无关（翻车 #2）。
**检查两处**：左下 Build Output 无红字 `Error #550`；`Options for Target→Device` 显示 **STM32F103C8**。

### 步骤 3 · 认识工程（30 秒）

| 位置 | 干嘛的 |
|---|---|
| `User/main.c` | 你的代码全写这（本教程主战场） |
| `User/stm32f10x_conf.h` | 标准库总开关：用哪个外设放开哪个 include，同时把对应 .c 加进工程 |
| `User/stm32f10x_it.c` | 所有中断函数写这 |
| `Libraries/CMSIS/...` | 启动文件 + stm32f10x.h（寄存器定义）+ SystemInit |
| `Libraries/STM32F10x_StdPeriph_Driver/` | 标准库外设驱动（脚手架只放了 rcc/gpio/misc，用一章加一章） |
| `MDK-ARM/*.uvprojx` | Keil 工程本体 |

**三个宏定身份**（Options→C/C++→Define）：`STM32F10X_MD`（中密度芯片）、`USE_STDPERIPH_DRIVER`（允许引入 conf.h）。

### 步骤 4 · 编译

**做**：Keil 里按 **F7**。
**我看到的（实测日志）**：

```
Program Size: Code=2816 RO-data=268 RW-data=40 ZI-data=1632
".\Objects\f103-spl-lab.axf" - 0 Error(s), 0 Warning(s).
```

**为什么**：四个数字=代码/常量/已初始化变量初值/零初始化变量。**Flash 占用=前三个之和（3124B/64KB），RAM=后两个之和（1672B/20KB）**。编译四步：汇编启动文件→编 .c→链接→FromELF 出 hex。

### 步骤 5 · 烧录（三种方法，选一个顺手的）

**方法 A · 图形界面（新手推荐）**：开 STM32CubeProgrammer → 右上选 **ST-LINK** → **Connect** → **Open file** 选 `Objects\f103-spl-lab.hex` → **Download**。看到 `File download complete` 即成功。

**方法 B · 命令行（快）**：

```
STM32_Programmer_CLI -c port=SWD -w Objects\f103-spl-lab.hex -v -rst
```

**方法 C · Keil 一键（一劳永逸）**：`Options→Debug` 选 **ST-Link Debugger**（Settings 里能看到序列号）→ `Flash Download` 点 **Add** 选 **STM32F10x Med-density Flash (128K)**，勾 **Reset and Run** → `Utilities` 确认用同一调试器 → OK。以后 **F7 编译 + LOAD 烧录**。

**实测日志（方法 B）**：

```
Erasing internal memory sectors [0 3]
Download in Progress ... 100%
Download verified successfully      ← 读回逐字节比对通过
MCU Reset                           ← 复位，程序开跑
```

**为什么两根线（SWDIO/SWCLK）就能烧录**：C8T6 出厂自带调试口，SWD 协议直通 Flash 控制器，擦写全由调试器代劳——所以芯片"变砖"也救得回来。

## 02 · 点亮 LED（1 秒闪烁）

### 步骤 6 · 看原理图，定引脚（在哪看/看什么/为什么）

**在哪看**：原理图 P3 "LED and Key Driver" 区。
**看什么**：

```
3.3V ──►|──[4.7K]──●── 网络(PC13)     ◄── 引脚拉低时电流流过 → 亮
      LED(绿)  限流电阻
```

**为什么是低电平点亮**：电流路径是 3.3V→LED→电阻→**引脚**→GND。引脚输出 0V，电路才有压差、电流才流动。**引脚输出低 = 亮，输出高 = 灭**——从电路推出来的，不是抄的。
**电流账**：(3.3−2.0−0.2)/4.7K ≈ 0.23mA。PC13/14/15 是备份域脚（灌电流建议≤3mA），4.7K 把电流压到安全余量 10 倍以上——这就是电阻用 4.7K 不是 470Ω 的原因。

### 步骤 7 · GPIO 模式：为什么选推挽输出

GPIO 八种模式（`stm32f10x.h` 枚举）：

| 模式 | 用途 |
|---|---|
| 输入浮空/上拉/下拉 | 读外部电平（按键用上拉） |
| 模拟输入 | ADC |
| 开漏输出 | 只能拉低，高电平靠外部上拉（I2C） |
| **推挽输出** | **能主动输出高和低 → 点灯用这个** |
| 复用推挽/开漏 | 引脚交给外设（串口 TX、硬件 I2C） |

**推挽 = 两个 MOS 管一推一挽**：上面 P-MOS 接 3.3V 负责"推高"，下面 N-MOS 接 GND 负责"拉低"。开漏只有下面的管子，输出高时引脚悬空——所以点灯不用它。
**速度选 2MHz**：翻转越快干扰（EMI）越大，LED 1Hz 闪烁 2MHz 绰绰有余——够用就好。

### 步骤 8 · 为什么先开时钟

**不开时钟 = 外设断电 = 寄存器写不进去**。GPIOC 挂在 **APB2** 总线上：

```c
RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOC, ENABLE);
```

这一行背后就一句：`RCC->APB2ENR` 的 bit4 置 1。以后 HAL/寄存器仓库会看到同一件事的另两种写法，**写法不同，动作相同**。

### 步骤 9 · 写代码（全码在 User/main.c，逐段讲）

```c
#include "stm32f10x.h"

/* SysTick 毫秒延时：内核自带 24 位递减计数器，时钟源 HCLK/8。
   1ms 需要计数 SystemCoreClock/8/1000 次。
   先 SystemCoreClockUpdate() 实测频率再算——防"变量说是 72M 实际只有 8M"的坑。 */
void delay_ms(uint32_t ms)
{
    uint32_t tick = SystemCoreClock / 8 / 1000;
    SysTick->LOAD = tick - 1;                    /* 重装值 */
    SysTick->VAL  = 0;                           /* 清计数 */
    SysTick->CTRL = SysTick_CTRL_ENABLE_Msk;     /* 启动 */
    while (ms--)
        while ((SysTick->CTRL & SysTick_CTRL_COUNTFLAG_Msk) == 0)
        { }                                      /* 计到 0 硬件置位，读后自动清 */
    SysTick->CTRL = 0;                           /* 关闭 */
}

int main(void)
{
    GPIO_InitTypeDef gpio;

    SystemCoreClockUpdate();                              /* 实测时钟频率 */
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOC, ENABLE); /* ① 开 GPIOC 时钟 */

    gpio.GPIO_Pin   = GPIO_Pin_13;                        /* ② PC13（绿灯） */
    gpio.GPIO_Mode  = GPIO_Mode_Out_PP;                   /*    推挽输出 */
    gpio.GPIO_Speed = GPIO_Speed_2MHz;                    /*    低速够用 */
    GPIO_Init(GPIOC, &gpio);                              /* ③ 写入 CRH 寄存器 */

    GPIO_WriteBit(GPIOC, GPIO_Pin_13, Bit_SET);           /* ④ 上电先灭 */

    while (1)
    {
        GPIO_WriteBit(GPIOC, GPIO_Pin_13, Bit_RESET);     /* 低 = 亮 */
        delay_ms(1000);
        GPIO_WriteBit(GPIOC, GPIO_Pin_13, Bit_SET);       /* 高 = 灭 */
        delay_ms(1000);
    }
}
```

**GPIO_InitTypeDef 落到哪**：GPIO 的 CRL/CRH 寄存器**每 4 位管一个脚**（CNF 2 位选模式 + MODE 2 位选速度）。PC13 在 CRH 的 [23:20]。`GPIO_Init` 干的事就是往这 4 位写 `0b0010`——寄存器版教程里你会亲手写它。
**隐藏坑**：`SystemCoreClock` 是编译期常量（72M），若板上晶振没焊/虚焊，SystemInit 会静默回落 HSI 8MHz，延时全慢 9 倍。`SystemCoreClockUpdate()` 读寄存器实测，两头都准。**实测本板有晶振（TKC8.000），1 秒节奏准。**

## 翻车档案（每个坑都真金白银）

| # | 现象 | 原因 | 解法 |
|---|---|---|---|
| 1 | Keil 报 `Error #550: Requested device...`，命令行编译却正常 | DFP 只装了 `C:\Keil_v5\ARM\PACK`，这份 Keil 的 GUI 读 `AppData\Local\Arm\Packs` | 两个目录都放一份 DFP |
| 2 | Pack Installer 弹 `Cannot move file index.pidx` | 联网刷新索引被占用 | 点取消，关掉它，不影响编译 |
| 3 | Keil 按 LOAD 烧不进去 | 工程没配调试器（默认仿真器） | 步骤 5 方法 C 四步配置 |
| 4 | 原理图 LED2=红(PC13)、LED1=绿(PC14)+继电器；实物却是 PC13=绿、PC14 只有继电器 | 原理图 v1.3 与实物有出入 | **实测定案**：PC13 绿灯可控制，PC14 控制继电器，PWR 常亮 |
| 5 | LED 不亮的 90% 原因 | 时钟开关写在 GPIO_Init 之后 | 时钟使能必须在配置前 |
