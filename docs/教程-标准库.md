## 1. 开发板与硬件事实

本教程使用的开发板为 **STM32F103C8T6 精英板（嘉立创 EDA 绘制，v1.3）**。

**知识点：为什么先讲原理图？**
AI/人写驱动代码的第一依据不是"网上怎么写"，而是**这块板的原理图**——LED 接在哪个引脚、是高电平亮还是低电平亮、按键有没有上拉，全部由原理图决定。不看原理图照抄代码，是新手"代码一模一样却不亮"的头号原因。

本板关键硬件事实（全部来自原理图，经人工逐区核对）：

| 外设 | 引脚 | 电气事实 |
|---|---|---|
| LED1（绿） | PC14 | 3.3V → LED → 4.7K → 引脚，**低电平点亮** |
| LED2（红） | PC13 | 同上，低电平点亮（PC13 属 RTC 备份域，驱动能力弱） |
| 蜂鸣器 | PC15 | NPN 三极管驱动，**高电平响** |
| 继电器 | PC14 | 与 LED1 共用引脚，高电平吸合 |
| 按键 KEY1/2/3 | PB7 / PB6 / PB5 | 按下接 GND，**低电平有效**，需开内部上拉 |
| 日志串口 | PA9(TX) / PA10(RX) | USART1，经板载 CH340N 转 USB TypeC |
| OLED | PB8(SCL) / PB9(SDA) | SSD1306，软件模拟 I2C（这两个脚不是硬件 I2C） |
| Flash | PB12~PB15 | W25Q128，SPI2 |
| ESP8266 | PA2 / PA3 | USART2 |

> 原理图 PDF 保存在本地 `docs/schematics/`（因版权原因**不随仓库上传**）。芯片手册在 `docs/datasheets/`。

## 2. 三种实现方式：为什么这套教程要写三遍

同一个"LED 1 秒闪烁"，我们会用三种方式实现：

| 方式 | 代码长什么样 | 优点 | 缺点 |
|---|---|---|---|
| **标准库 SPL**（本仓库） | `GPIO_Init(GPIOC, &gpio)` 封装函数 | 与寄存器一一对应又不用背地址；大量老教材/老项目在用 | ST 已停止维护，新项目首选 HAL |
| **HAL 库** | `HAL_GPIO_WritePin(...)` | CubeMX 图形化生成、可移植全系列、官方主推 | 封装太厚，难看清寄存器 |
| **寄存器** | `GPIOC->CRH = ...` | 最快最小、彻底理解芯片 | 记地址/位定义，开发效率低 |

**学习顺序：标准库 → HAL → 寄存器**。标准库的函数名（如 `RCC_APB2PeriphClockCmd`）和它操作的寄存器（`RCC->APB2ENR`）对应关系最直白，是理解另两种方式的最佳桥梁。

## 3. 软件安装（一次性）

### 3.1 Keil MDK5（IDE + 编译器）

1. 安装 Keil MDK5（本教程验证环境：Keil v5.x，`C:\Keil_v5`）。
2. **编译器用 AC5（ARMCC V5.06）**。安装 MDK 时勾选 "ARM Compiler 5"；若 Keil 新版默认只装 AC6，需在 Pack Installer 或安装包里补装 AC5。
   - **知识点：为什么必须 AC5？** 工程里的启动文件 `startup_stm32f10x_md.s` 是 ST 2011 年发布的 **ARM 语法汇编**（`AREA`、`PROC` 等伪指令）。AC6（armclang）只认 GNU 语法汇编，遇到 ARM 语法会报错。所以三条腿全部用 AC5，这是老启动文件决定的选择，不是随意指定。

### 3.2 DFP 芯片支持包（本工程依赖 Keil::STM32F1xx_DFP 2.3.0）

**知识点：DFP 是什么？** DFP（Device Family Pack，设备族包）是 Keil 的"芯片说明书"压缩包：里面装着这颗芯片的 Flash 擦写算法（.FLM）、SVD 寄存器描述、设备参数。**没有它，Keil 新建/打开工程时找不到 STM32F103C8 这个芯片，也烧不了录**。它和编译方式（Keil/CMake）无关，纯 Keil 侧的芯片支持。

安装方法（二选一）：
- 方法 A：Keil 菜单 `Pack Installer` → 搜 `STM32F1xx_DFP` → Install（需要网络）；
- 方法 B：从 keil.arm.com 下载 `Keil.STM32F1xx_DFP.2.3.0.pack`，双击安装。
- 验证：Keil 打开本工程 → `Project → Options → Device` 能看到 **STM32F103C8**；`Flash → Configure Flash Tools` 里 Flash 算法为 `STM32F10x Med-density Flash (128K)`。

### 3.3 烧录工具：ST-Link 驱动 + STM32CubeProgrammer

1. 装好 ST-Link 驱动（ST 官网 SWUMSC55 或装 ST-LINK Utility 时自带）。
2. 安装 **STM32CubeProgrammer**（ST 官方烧录器，命令行 `STM32_Programmer_CLI` 在 PATH 或安装目录 `bin` 下）。
3. 接线：ST-Link 的 SWDIO/SWCLK/GND/3.3V 接板子 SWD 排针。
   - **知识点：SWD 是什么？** Serial Wire Debug，两线调试协议（SWDIO 数据 + SWCLK 时钟），占用 PA13/PA14。它同时承担**烧录**和**在线调试**，复位后芯片的调试口永远可用，所以"芯片锁死也能重新烧录"。

### 3.4 CH340 驱动（阶段三串口才用，建议顺手装好）

板载 CH340N 把 USART1 转成 USB。装 CH340 驱动后，板子插 USB 会出现 COM 口。

## 4. 打开工程并编译

### 步骤
1. 双击 `MDK-ARM/f103-spl-lab.uvprojx` 打开工程。
2. 点 `Rebuild`（F7）。预期输出：

```
Program Size: Code=852 RO-data=268 RW-data=20 ZI-data=1636
".\Objects\f103-spl-lab.axf" - 0 Error(s), 0 Warning(s).
```

### 知识点：Program Size 四个数字是什么？

| 名字 | 含义 | 去向 |
|---|---|---|
| Code=852 | 代码段 | Flash |
| RO-data=268 | 常量（const） | Flash |
| RW-data=20 | 已初始化全局变量 | Flash 存初值 + 上电拷到 RAM |
| ZI-data=1636 | 零初始化变量/栈/堆 | RAM |

Flash 占用 = Code + RO + RW = **1172 B / 64KB**；RAM = RW + ZI = **1656 B / 20KB**。

### 知识点：编译四步都发生了什么

按 F7 时 Keil 依次执行：
1. **汇编** `startup_stm32f10x_md.s` → 生成向量表和复位代码；
2. **编译** 各 `.c` → `.o`（`--c99 --apcs=interwork`，宏 `USE_STDPERIPH_DRIVER,STM32F10X_MD` 在此注入）；
3. **链接** → 分配地址生成 `f103-spl-lab.axf`；
4. **FromELF** → 生成 `hex`（烧录用）。

## 6. 工程结构逐个讲（脚手架里每个文件是干嘛的）

```
f103-spl-lab/
├─ User/
│  ├─ main.c                 # 主函数。main() 前发生了什么见第 8 节
│  ├─ stm32f10x_it.c/.h      # 所有中断服务函数集中在这里（函数名=启动文件向量表标号）
│  └─ stm32f10x_conf.h       # SPL 总开关：用哪个外设就放开哪个 #include，
│                            # 并把 Libraries/STM32F10x_StdPeriph_Driver/src 下对应 .c 加入工程
├─ Libraries/
│  ├─ CMSIS/CM3/CoreSupport/ # ARM 官方 Cortex-M3 内核层（core_cm3.h 定义内核寄存器/NVIC/SysTick）
│  └─ CMSIS/CM3/DeviceSupport/ST/STM32F10x/
│     ├─ stm32f10x.h         # ★ 芯片总头文件：定义 STM32F10X_MD 时展开全部外设寄存器结构体
│     ├─ system_stm32f10x.c  # SystemInit()：上电第一个被调用的 C 函数（时钟基础配置）
│     └─ startup_stm32f10x_md.s # 启动文件：向量表 + 复位后第一段代码（ARM 语法，须 AC5）
│  └─ STM32F10x_StdPeriph_Driver/
│     ├─ inc/                # SPL 全部外设头文件（保留全量，头文件不占空间）
│     └─ src/                # 脚手架仅放 rcc/gpio/misc 三个 .c（最小可编译），按章追加
└─ MDK-ARM/
   └─ f103-spl-lab.uvprojx   # Keil 工程（Device=STM32F103C8，AC5，C99）
```

**知识点：三个宏决定了整个工程的"身份"**
- `STM32F10X_MD`：Medium Density（中密度）= Flash 64~128K 的 F103（C8T6 属于它）。它让 `stm32f10x.h` 只展开中密度芯片有的外设（C8T6 没有 FSMC/SDIO，定义成 HD 就会编出错误代码）。
- `USE_STDPERIPH_DRIVER`：允许 `stm32f10x.h` 把 `stm32f10x_conf.h` 引进来。不定义它，SPL 一个头都进不来。
- `STM32F10X_MD` 与后续 HAL 仓库的 `STM32F103xB` **不是一套体系**：SPL 用"密度"命名，HAL 用"型号族"命名，见 HAL 仓库 01 章对比。

**知识点：为什么 src 只放 3 个 .c？**
SPL 每个外设的驱动是独立 .c。全加进去编译慢、镜像大；`stm32f10x_conf.h` 注释掉的外设即使 .c 在工程里也没意义。所以规矩是：**conf.h 放开 include ↔ 工程里加对应 .c，两步必须同时做**。02 章点灯恰好只需要 rcc/gpio。

## 7. 上电到 main()：启动全链路（重点知识点）

```
按下复位
  → CPU 从地址 0x08000000 取栈顶指针 SP、取复位向量 PC
  → startup_stm32f10x_md.s: Reset_Handler
      1) 调 SystemInit()（system_stm32f10x.c：默认 HSI 8MHz，安全起跑）
      2) 调 __main（C 库入口：把 RW 初值从 Flash 搬到 RAM、清零 ZI、建堆栈）
  → 跳进 main()
```

**知识点：为什么向量表在 0x08000000？** C8T6 的 Flash 映射在 0x08000000，复位后 CPU 固定从地址 0 取 SP 和 PC。启动文件开头 `DCD` 的一串地址就是向量表（第 0 项=栈顶、第 1 项=Reset_Handler、之后是各中断）。地址 0 处实际是 Flash 的别名映射。

**知识点：SystemInit 只把时钟调到"能跑"，不等于 72MHz。** 脚手架保持默认 HSI 8MHz（最安全）；02 章会用 `SystemCoreClock` 与 SysTick 实现精确 1s 闪烁时再讲倍频到 72MHz 的完整时钟树。

## 2.0 先回答三个高频疑问

### Q1：点灯需要接什么线？

**LED 不需要接任何线。** LED1/LED2 已经焊在板上，限流电阻也焊好了，我们的工作是"控制"它们而不是"连接"它们。真正要接的线只有一根——**ST-Link 调试器到板子**（用来烧录程序，见 2.6 节）。

### Q2：ST-Link 接到板子哪里？（重要，需要你看一眼实物）

先说原理图查证结果（本教程一切以证据为准）：**这份原理图上没有画出 SWD 调试座**。两个 20P 排针 J1/J2 的完整引脚定义如下（来自原理图 P2 放大精读）：

| J1 脚号 | 网络 | J1 脚号 | 网络 |
|---|---|---|---|
| 1 | 3V3 | 11 | PA15 |
| 2 | GND | 12 | PA12 |
| 3 | +5V | 13 | PA11 |
| 4 | PB9 | 14 | PA10 |
| 5 | PB8 | 15 | PA9 |
| 6 | PB7 | 16 | PA8 |
| 7 | PB6 | 17 | PB15 |
| 8 | PB5 | 18 | PB14 |
| 9 | PB4 | 19 | PB13 |
| 10 | PB3 | 20 | PB12 |

| J2 脚号 | 网络 | J2 脚号 | 网络 |
|---|---|---|---|
| 1 | 3V3 | 11 | PA6 |
| 2 | PC13 | 12 | PA7 |
| 3 | PC14 | 13 | PB0 |
| 4 | PC15 | 14 | PB1 |
| 5 | PA0 | 15 | PB10 |
| 6 | PA1 | 16 | PB11 |
| 7 | PA2 | 17 | RST（复位） |
| 8 | PA3 | 18 | 3V3 |
| 9 | PA4 | 19 | GND |
| 10 | PA5 | 20 | GND |

注意：**J1/J2 上没有 PA13(SWDIO) 和 PA14(SWCLK)**。C8T6 的 SWD 走的就是这两个脚，原理图却没引出——所以请你看一眼**实物板**，按下面三步确认（30 秒）：

1. **找专用 SWD 座**：板边有没有 4 针小排针/焊盘，丝印类似 `SWD`、`SWIO/CLK`、`DIO/DCK`、`3V3/SWDIO/SWCLK/GND`？很多板子有，但原理图偷懒没画。
2. **看排针丝印**：J1/J2 针脚旁的白色丝印上有没有 `PA13`/`PA14` 或 `SWDIO`/`SWCLK`？（原理图漏画、实物有，自制板常见。）
3. **都没有** → 走"串口 ISP 烧录"备选方案（2.6 节方案 B，用板载 CH340N + BOOT0，不接 ST-Link 也能烧）。

**✅ 已实物确认（2026-10-04，照片证据）**：SWD 座就在**核心板左边缘的 4 针黑色座**上，丝印从左到右 `GND / SWCLK / DIO / 3.3`。实测接法：

| ST-Link 侧 | 板子侧（核心板 4P 座） | 说明 |
|---|---|---|
| SWDIO | DIO | 调试数据线 |
| SWCLK | SWCLK | 调试时钟线 |
| GND | GND | 共地，必须接 |
| 3.3V | 3.3 | 可不接（板子用 USB 供电时） |

**关键教训**：原理图上完全没画这个 SWD 座（U3 符号省略了 PA13/PA14 脚）——**原理图≠实物，关键接口必须实物核对**。这块板其实是"核心板（蓝色，含 C8T6 + 8MHz 晶振 + BOOT0 跳线）+ 底板（黑色，全部外设）"的二合一结构，J1/J2 两个 20P 排针就是两块板之间的连接器。

**知识点：为什么推荐板子用 USB 供电、ST-Link 不接 3.3V？** 板子 TypeC 口插电脑 USB 就有 5V（经板载 DC-DC → 5V、LDO → 3.3V）。如果 ST-Link 也给 3.3V，两路电源会在 3.3V 轨上"打架"（电压稍有差异就互灌电流）。经验做法：**板子吃自己的 USB 电，ST-Link 只接 SWDIO/SWCLK/GND 三根线**。

### Q3：标准库开发需要装 CubeMX 吗？

**不需要。** 三个工具的分工要分清：

| 工具 | 是干嘛的 | 本仓库用不用 |
|---|---|---|
| Keil MDK5 | 写代码 + 编译（编辑器+编译器+调试界面） | ✅ 主力 |
| STM32CubeMX | 图形化点引脚/配时钟，**一键生成 HAL 库工程** | ❌ 标准库用不上（它是 HAL 生态的配置器） |
| STM32CubeProgrammer | 把编译出的 hex/elf 烧进芯片 | ✅ 烧录 |
| 串口助手 | 看板子打出来的日志 | 03 章串口时用 |

一句话：**CubeMX 是 HAL 的"外挂"，标准库时代（2011 年发布）它还没出生**。标准库工程就是 Keil 里手写代码，没有任何生成器。HAL 仓库后续章节才会用到"AI 输出 CubeMX 配置清单 → 你在 CubeMX 里点 → 生成代码"的协作方式。

## 2.1 第一步：看原理图，找到 LED 电路（教你读图）

原理图 P3 左下角"LED and Key Driver"区，LED 电路长这样（文字化描述）：

```
3V3 ──►|──[R12 4.7K]──●  网络LED1 ◄── 接 PC14   （LED1 = 绿色）
3V3 ──►|──[R11 4.7K]──●  网络LED2 ◄── 接 PC13   （LED3 = 红色）
        发光二极管，三角►|指向阴极
```

**读图三要素**（以后每章都这么读）：

1. **顺着网络标号走**：原理图不把所有线画在一页，**同名网络标号就是同一根电线**。`LED1` 这个名字出现在 Pin Mapping 区（右端接 PC14），又出现在 LED 驱动区（LED 阴极）——两处就是一根线。
2. **二极管方向 = 电流方向**：`►|` 符号的三角指向阴极。这里三角指向电阻一侧（指向引脚），意思是电流从 3V3 流向引脚。
3. **电阻是限流的**：LED 不能直连电源，必须串电阻限流，否则烧 LED/烧引脚。

### 知识点：为什么是"低电平点亮"？（本章最重要的一个为什么）

LED 要亮，必须有**电流流过**它。这个电路里电流路径只有一条：

```
3.3V ──► LED ──► 4.7K ──► PC14 引脚 ──► (芯片内部) ──► GND
```

电流要从 PC14"流进去"（专业术语叫**灌电流，sinking current**），PC14 必须输出 **0V（低电平）**，电路里才有 3.3V→0V 的压差，电流才流动，LED 亮。

反过来 PC14 输出 3.3V（高电平）时，LED 两端都是 3.3V，没有压差、没有电流，LED 灭。

**结论：代码里"输出低电平 = 亮，输出高电平 = 灭"。** 这个结论不是从例程抄的，是从电路推出来的——如果哪块板 LED 接法相反（引脚→电阻→LED→GND），那就是"高电平点亮"，一切以原理图为准。

**顺便算一笔电流账**（为什么要这个 4.7K 电阻）：

LED 压降 Vf ≈ 2.0V（红色），电流 I = (3.3V − 2.0V − 0.2V引脚压降) / 4.7K ≈ **0.23mA**。

PC13/PC14/PC15 这三个脚是**备份域引脚**，芯片手册要求驱动能力弱（灌电流建议 ≤3mA）。0.23mA << 3mA，**安全余量 10 倍以上**——这就是设计者用 4.7K 而不是 470Ω 的原因：备份域脚带不动的负载，用大电阻把电流压下来。

**知识点：备份域是什么？** PC13~PC15 属于 VBAT 供电的"RTC 后备区"，即使主电源断电（纽扣电池顶上）这部分还在走。代价是这仨脚很"弱"：只能小电流、只能低速（≤2MHz），而且如果以后启用了 LSE 低速晶振（给 RTC 用），PC14/PC15 就不能当 GPIO 了。我们的工程不用 RTC，所以它们能当普通输出口——但记住只能带"轻负载"（LED、信号），不能带继电器线圈这种大电流负载。

## 2.2 GPIO 是什么：八种模式，为什么选"推挽输出"

GPIO = General Purpose Input/Output，通用输入输出口。每个引脚可配成 8 种模式（`stm32f10x.h` 里的枚举）：

| 模式 | 枚举值 | 用途举例 |
|---|---|---|
| 输入浮空 | GPIO_Mode_IN_FLOATING | 外部已有确定电平（如另一芯片输出） |
| 输入上拉 | GPIO_Mode_IPU | **按键**（按下拉低，平时内部上拉读高） |
| 输入下拉 | GPIO_Mode_IPD | 按下拉高型的按键 |
| 模拟输入 | GPIO_Mode_AIN | ADC 采样 |
| 开漏输出 | GPIO_Mode_Out_OD | 只能拉低，高电平靠外部上拉（I2C 总线专用） |
| **推挽输出** | GPIO_Mode_Out_PP | **驱动 LED**：既能主动输出高也能主动输出低 |
| 复用推挽 | GPIO_Mode_AF_PP | 引脚交给外设控制（如 USART 的 TX） |
| 复用开漏 | GPIO_Mode_AF_OD | 外设 + 开漏（硬件 I2C） |

**为什么点 LED 选推挽（Push-Pull）输出？**

"推挽"= 两个晶体管一推一挽：上面 P-MOS 负责"推"出高电平（连通 3.3V），下面 N-MOS 负责"拉"到低电平（连通 GND）。两个方向都有主动驱动能力——我们要主动把引脚拉到 0V（亮）和 3.3V（灭），正合适。

开漏（OD）为什么不行？开漏只有下拉的 N-MOS：输出"低"没问题，输出"高"时引脚**悬空**（要靠外部上拉电阻慢慢拉上去），边沿软、还得外接电阻——那是 I2C 总线的要求，点灯没必要。

**知识点：输出速度为什么选 2MHz？** GPIO_Speed 是输出边沿的翻转速度上限（2/10/50MHz 三档）。速度越高边沿越陡、电磁干扰（EMI）越大、功耗越高。LED 闪烁 1Hz，2MHz 绰绰有余——**速度给够就好，不要拉满**。备份域脚 PC13~15 本来也只支持低速。

## 2.3 时钟：为什么先"打开 GPIOC 的时钟"才配 GPIO

STM32 每个外设（GPIO/USART/SPI…）前面都有一道**时钟闸门**（时钟门控 clock gating）：闸门不开，外设就是断电状态——**寄存器写了也写不进去**。

C8T6 的时钟分三层总线：

```
SYSCLK(最高72MHz)
 ├─ AHB ────► DMA、CRC…
 │            ├─ APB2(72MHz) ──► GPIOA~C、USART1、ADC、SPI1、AFIO、TIM1
 │            └─ APB1(36MHz) ──► USART2/3、I2C、SPI2、TIM2~4
```

GPIOC 挂在 **APB2** 上，开时钟的标准库语句：

```c
RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOC, ENABLE);
```

**知识点：这行代码背后发生了什么？** 它等价于对 `RCC->APB2ENR` 寄存器的 bit4（IOPCEN）写 1。标准库函数只是"位操作的可读化包装"——以后在 HAL/寄存器仓库会看到同一件事的另外两种写法（`__HAL_RCC_GPIOC_CLK_ENABLE()` 和 `RCC->APB2ENR |= RCC_APB2ENR_IOPCEN`）。**三个仓库写法不同，物理动作完全相同**——这正是三线并行学习的价值。

**知识点：为什么 GPIO 挂 APB2？** 老牌高速外设（GPIO/USART1/ADC/SPI1）在 APB2（72MHz），低速外设（USART2/I2C/SPI2）在 APB1（36MHz，最多为 SYSCLK 的一半）。以后配 USART2 时开时钟用的是 `RCC_APB1PeriphClockCmd`——不用背，查数据手册总线表，或直接问 AI。

## 2.4 写代码（完整代码 + 逐段讲）

打开 `User/main.c` 替换为下面内容，**每行注释都说明为什么**：

```c
/**
  ******************************************************************************
  * @file    main.c
  * @brief   02 章：LED 1 秒闪烁（标准库）
  * @note    LED1=PC14（绿，低电平亮，与继电器共用）；LED2=PC13（红，低电平亮）
  ******************************************************************************
  */
#include "stm32f10x.h"

/* ---------- SysTick 精确毫秒延时 ----------
 * SysTick 是 Cortex-M3 内核自带的 24 位递减计数器，不占用芯片外设。
 * 时钟源选 HCLK/8：计数一次 = 8/SystemCoreClock 秒。
 * 1ms 需要计数 SystemCoreClock/8/1000 次。
 * 不写死 72000 而用实测值——原因见本节末尾"隐藏大坑"。
 */
void delay_ms(uint32_t ms)
{
    uint32_t tick = SystemCoreClock / 8 / 1000;   /* 1ms 的计数次数 */
    SysTick->LOAD = tick - 1;                     /* 重装值 */
    SysTick->VAL  = 0;                            /* 清当前计数值 */
    SysTick->CTRL = SysTick_CTRL_ENABLE_Msk;      /* 使能（CLKSOURCE=0 → HCLK/8） */
    while (ms--)
    {
        /* COUNTFLAG 计到 0 由硬件置 1，CPU 读一次自动清零 */
        while ((SysTick->CTRL & SysTick_CTRL_COUNTFLAG_Msk) == 0)
        {
        }
    }
    SysTick->CTRL = 0;                            /* 用完关闭 */
}

int main(void)
{
    GPIO_InitTypeDef gpio;                        /* 标准库的"配置单"结构体 */

    /* 0) 实测当前系统时钟写入 SystemCoreClock 变量（delay 依赖它）
     *    原理图上没有画外部晶振：HSE 若起振失败，SystemInit() 会
     *    静默回落到 HSI 8MHz。SystemCoreClockUpdate() 读 RCC 寄存器
     *    现场计算真实频率，72M 或 8M 都准确——不猜，以实测为准。 */
    SystemCoreClockUpdate();

    /* 1) 打开 GPIOC 时钟（APB2）——不开时钟，下面的配置写不进去 */
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOC, ENABLE);

    /* 2) 填"配置单"：PC13+PC14 推挽输出 2MHz */
    gpio.GPIO_Pin   = GPIO_Pin_13 | GPIO_Pin_14;  /* LED2=PC13, LED1=PC14 */
    gpio.GPIO_Mode  = GPIO_Mode_Out_PP;           /* 推挽输出（2.2 节选它的理由） */
    gpio.GPIO_Speed = GPIO_Speed_2MHz;            /* 1Hz 闪烁，低速即可 */

    /* 3) 应用配置单（内部写 GPIOC 的 CRH 寄存器，见下方拆解） */
    GPIO_Init(GPIOC, &gpio);

    /* 4) 上电先输出高电平（两灯灭），再进闪烁循环 */
    GPIO_WriteBit(GPIOC, GPIO_Pin_13 | GPIO_Pin_14, Bit_SET);

    while (1)
    {
        /* 低电平 → 两灯亮（注意：PC14 同时驱动继电器吸合，会"咔哒"一声） */
        GPIO_WriteBit(GPIOC, GPIO_Pin_13 | GPIO_Pin_14, Bit_RESET);
        delay_ms(1000);                           /* 亮 1 秒 */

        /* 高电平 → 灭 */
        GPIO_WriteBit(GPIOC, GPIO_Pin_13 | GPIO_Pin_14, Bit_SET);
        delay_ms(1000);                           /* 灭 1 秒 */
    }
}
```

**只想点一颗？** 把代码里 `GPIO_Pin_13 | GPIO_Pin_14` 中的 `| GPIO_Pin_14` 删掉，只留 PC13（LED2），其余不变——这样继电器不会咔哒响。

### 知识点：GPIO_InitTypeDef 三个字段最终写到了哪个寄存器

标准库 `GPIO_Init()` 的本质：GPIOC 的 CRL/CRH 寄存器**每 4 位管一个脚**（CNF[1:0] 模式选择 + MODE[1:0] 速度/方向）：

| 字段 | 你填的值 | 落到寄存器的哪里 |
|---|---|---|
| GPIO_Pin | `GPIO_Pin_14` | PC14 用 **CRH** 的 [19:16]（PC0~7 用 CRL，PC8~15 用 CRH） |
| GPIO_Mode | Out_PP | CNF=00（通用推挽输出） |
| GPIO_Speed | 2MHz | MODE=10（输出模式 @2MHz） |

也就是说 `GPIO_Init(GPIOC, &gpio)` 最终就是往 `GPIOC->CRH` 的 [19:16] 写 `0b0010`。寄存器仓库里你会亲手写这 4 个位——到时回头看这里，三条线就"打通"了。

### 知识点：隐藏大坑——SystemCoreClock 变量 ≠ 真实时钟

标准库 `SystemInit()` 上电会尝试把时钟配到 72MHz（外部 8M 晶振 × PLL 9 倍）。但**这份精英板原理图上没画晶振**——如果板上真没焊晶振（或虚焊），HSE 起振失败，`SetSysClockTo72()` 会**静默回落**到内部 HSI 8MHz 继续跑。此时代码里的 `SystemCoreClock` 变量却还是 72,000,000（编译期常量），**变量值 ≠ 真实时钟**——按 72M 算的 1ms 延时实际跑了 9ms，LED 变成"9 秒闪一次"。

`SystemCoreClockUpdate()` 读 RCC 寄存器**现场计算**真实频率写入变量，72M 或 8M 都准。这就是"不猜、以实测为准"在代码里的体现。（上板后看闪烁节奏还能反推板上有没有晶振：1 秒准 = HSE 72M 正常；9 秒 = 回落 HSI 8M，告诉我一声，后续时钟章节改用 HSI 方案。）
